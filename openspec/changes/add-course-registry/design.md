## Context

Мотивация — в proposal.md. Сейчас реестр (`src/lessons/registry.ts`) собирает уроки одного курса через `import.meta.glob`, модули (`ModuleId`) — общий литерал, название курса и названия модулей лежат в словарях интерфейса, а сессии уроков в Model ключуются одним `slug`. Палитра «Позже в курсе» (D8 из `add-course-lessons`) считается по всем урокам с `lesson.ts`. Параллельно другие исполнители правят `src/net/` (модель пакетов) и пишут сценарии уроков в `docs/plans/networks-lessons/`; эти пути изменение не трогает.

## Goals / Non-Goals

**Goals:**

- Новый курс или урок добавляется новой папкой, общие файлы не правятся.
- Модуль урока, языки и `unlocks` проверяются по своему курсу: типами там, где это возможно, и тестом реестра всегда.
- Старые ссылки на уроки и шаги продолжают работать.

**Non-Goals:**

- Контракт вида доски (`BoardKind`), квизы, доска `packet` — это `extract-board-kind`, `add-quiz-steps`, `add-network-board`.
- Метка «новое» на элементах и тест «всё, что урок использует, открыто» — их добавят поверхности, которые эти элементы рисуют. Здесь только данные и функции.
- Прогресс по курсам (`add-learning-progress`) и предрендер.

## Decisions

### D1. Файлы курса

```
apps/web/src/courses/
  model.ts  assemble.ts  registry.ts  unlocks.ts
  system-design/  course.ts  course.<язык>.ts  lessons/NN-slug/{meta.ts, lesson.ts, text.<язык>.ts}
  networks/       course.ts  course.<язык>.ts  features.ts  lessons/NN-slug/{meta.ts, text.<язык>.ts}
```

- `course.ts`: `defineCourse({ id, order, board, modules, features, locales })`.
  - `order` задаёт место в каталоге: System Design первым.
  - `board` — `'flow'` или `'packet'`.
  - `features` — набор элементов интерфейса, которые уроки курса могут открыть.
- `course.<язык>.ts`: `{ title, tagline, modules: { <модуль>: название } } satisfies CourseText<typeof course>`. Тип требует название каждого модуля.
- `meta.ts`: `defineLessonMeta(course, { slug, module, order, available, locales, unlocks? })`. Первый аргумент — описание своего курса. Через него `module` и `unlocks` проверяются типами, а в meta записывается id курса.
- Тексты урока и `lesson.ts` не меняются, меняются только относительные импорты.

Рассмотренные альтернативы:

- **Общий `ModuleId` на все курсы.** Отклонено: урок System Design мог бы объявить модуль сетей.
- **Курс по имени папки без `course.ts`.** Отклонено: негде объявить модули, вид доски и элементы.

### D2. Реестр и проверка

- `registry.ts` собирает пять наборов через `import.meta.glob`:
  - `./*/course.ts` и `./*/course.*.ts`;
  - `./*/lessons/*/meta.ts`, `./*/lessons/*/text.*.ts` и `./*/lessons/*/lesson.ts`.
- Чистая `assembleCatalog` (`assemble.ts`) строит курсы с уроками и список проблем. Тест реестра требует, чтобы проблем не было. Проблемы:
  - папка курса не равна `id`;
  - `id` не в kebab-case или зарезервирован (`lessons`);
  - повтор `id` или `order` курса;
  - нет или пуст текст курса на объявленном языке, есть текст на необъявленном;
  - урок в папке без курса;
  - `meta` урока объявлена с чужим курсом;
  - модуль урока не из модулей курса;
  - урок открывает элемент не из набора курса;
  - элемент открывают два урока;
  - все прежние проверки урока (имя папки, языки, пустые тексты, повтор slug или order), теперь в пределах курса и с префиксом `<курс>/<папка>`.
- Уроки курса сортируются по порядку модулей курса, затем по `order`.
- Поиск ведётся по паре «курс + slug»: `findCourse`, `findLesson`, `findDefinition`, `courseLessons`. Slug уникален только внутри курса.

### D3. Урок знает свой курс

- Model плеера получает поле `course`, а `Player.init(course, lesson, step)` — курс первым аргументом.
- Сессии уроков в корневой Model ключуются как `<курс>/<slug>` (`lessonKey`).
- Так одинаковые slug в разных курсах не смешиваются, а ключ «курс + урок + шаг» готов для `add-learning-progress` (раздел 4.1 плана).

Альтернатива — глобально уникальные slug. Отклонена: ограничение для авторов, а прогресс всё равно нужно ключевать курсом.

### D4. Маршруты

| Маршрут | Адрес |
|---|---|
| `Home` | `/:язык/` — каталог |
| `Course` | `/:язык/:курс/` |
| `Lesson` | `/:язык/:курс/lessons/:slug?step=N` |
| `LegacyLesson` | `/:язык/lessons/:slug?step=N` — только разбор |

- Сегмент курса — строка; неизвестный курс показывает «не найдено» так же, как неизвестный урок. Маршруты не зависят от реестра.
- `LegacyLesson` разбирается раньше `Course`, а `lessons` зарезервирован как id курса, поэтому старые адреса однозначны.
- Приход на `LegacyLesson` заменяет адрес командой `RedirectToCourse` (`replaceUrl`, история не засоряется) на урок курса `system-design` с тем же `step`. Дальше работает обычный путь входа в урок. Адрес без языка сначала получает язык, затем курс: две замены подряд, обе без записи в историю.
- Помощники печати: `homeUrl(locale)`, `courseUrl(locale, course)`, `lessonUrl({ locale, course, slug, step })`.

### D5. Тексты: курс отдельно от интерфейса

- Название, слоган и модули курса — контент курса (`course.<язык>.ts`). Если курса нет на языке страницы, он показывается на английском или на первом объявленном языке, как урок.
- В словарях интерфейса остаются строки сайта:
  - название сайта для логотипа;
  - слоган и заголовок каталога;
  - подпись переключателя курса;
  - код `UnknownCourse`.
- `courseTitle`, `courseTagline`, `home.moduleTitle` и `documentTitle` из словарей удаляются.
- Заголовок вкладки:
  - на странице курса и урока — «страница · курс»;
  - в каталоге — название сайта;
  - на «не найдено» — «не найдено · сайт».

### D6. `unlocks`: элементы интерфейса по урокам

- Набор элементов — литералы Schema своего курса. Для `networks` это `courses/networks/features.ts`: `UiFeature` по таблице 3.4 плана, имена вида `<поверхность>.<элемент>`.
  - Поверхности: `transport`, `board`, `quiz`, `wifi`, `browser`, `terminal`, `router`, `dnsPanel`, `vpn`.
  - Набор передаётся в `defineCourse({ features: UiFeature.literals })`.
  - У System Design набор пуст.
- Расчёт — чистые функции `unlocks.ts` над `{ order, unlocks }` уроков, как палитра D8:
  - `unlockedThrough` — всё открытое уроками до текущего включительно, в порядке открытия;
  - `unlockedIn` — открытое самим уроком, для будущей метки «новое»;
  - `isUnlockedThrough`.
- Для потребителей реестр даёт `isUnlocked(course, lessonOrder, feature)`, `unlockedFeatures(course, lessonOrder)` и `newFeatures(course, lessonOrder)`. Первый аргумент — описание курса из `course.ts` или из реестра; с описанием из `course.ts` имя элемента проверяется типом.
- Поверхность видна, если открыт хотя бы один её элемент. Отдельного элемента «поверхность» нет.

Альтернатива — сравнивать номер урока в коде поверхностей. Отклонена планом: урок из PR не должен менять код поверхностей.

### D7. Шапка, каталог, карта курса

- **Шапка:** логотип — название сайта, ведёт в каталог. Рядом навигация «Курс» со ссылками на карты курсов, текущий курс отмечен `aria-current`. Справа переключатель языка, как раньше.
- **Каталог:** карточка на курс — название-ссылка, слоган, число уроков и метка «скоро», пока в курсе нет доступных уроков.
- **Карта курса** — прежняя главная, параметризованная курсом. Название курса стоит в заголовке, модули из текстов курса.

## Risks / Trade-offs

- [Внешние ссылки на `/:язык/lessons/...` и закладки] → перенаправление со шагом, тест-история и проверка в браузере.
- [Длинные относительные импорты в уроках (`../../../../lesson/dsl`)] → так уже устроены уроки, алиасы путей — отдельное решение. В CONTRIBUTING показан готовый пример.
- [Название сайта для логотипа ещё не выбрано владельцем] → строка `siteTitle` в четырёх словарях, меняется в одном месте на язык.
