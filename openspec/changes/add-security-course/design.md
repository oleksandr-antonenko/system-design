## Context

Мотивация — в proposal.md. Платформа уже умеет всё, что нужно уроку-слайдам: шаги с текстом и доской, «Назад» / «Далее», шкалу шагов, ← →, `?step=N`, квизы с одной попыткой, карточку задачи с целями, подсказками и «Показать решение», поверхности задачи во вкладках, открытие интерфейса уроками (`unlocks`), тесты контента через контракт `BoardKind`. Демо курса (`docs/mockups/security-lesson-*.html`) показывают, как урок выглядит и ведёт себя; правила кадров, героев и картинок — в плане `docs/plans/security-course.md`, разделы 2, 4–7.

Ограничения: Foldkit (Model только из Schema, сообщения — факты, эффекты — команды), четыре языка с проверкой полноты типами, урок — модуль папки, никаких правок общих файлов ради одного урока.

## Goals / Non-Goals

**Goals:**

- Урок курса безопасности — обычный урок платформы на новом виде доски; плеер, квизы, задачи, журнал и тесты контента работают без особых случаев.
- Один шаг — один кадр с текстом; кадры листает только ученик.
- Экраны (телефон, почта, страница-двойник) проверяются по состоянию, а ошибки на них учат, а не тупят.
- Введённое на странице-двойнике не попадает никуда, и это доказано тестом.

**Non-Goals:**

- Уроки 2, 4, 6, 10, 11 (остаток MVP) и волна В2 — только заглушки «скоро».
- Сертификат урока 12, сохранение прогресса между визитами.
- Анимированные вставки мультика (вопрос владельцу 3 плана).
- Настройки «под компанию» (вопрос 2 плана).

## Decisions

### D1. Новый вид доски `scenario`, а не доска сетей

Документ `packet` — топология и пакеты; почте, странице входа, менеджеру паролей, мессенджеру и чату с ИИ в нём места нет, а кадр мультика — не схема. Свой вид за тем же контрактом `BoardKind` даёт плееру, квизам, задачам, журналу и тестам контента всё как есть.

Отклонено: (а) уроки курса на `packet` — подходит только урок 1, и то без почты; (б) отдельный «урок-слайдшоу» мимо `BoardKind` — пришлось бы повторить плеер, квизы, задачи и проверку контента.

Новый вид — по правилу AGENTS.md: папка `kinds/scenario/`, варианты в каждом union `kinds/state.ts` (`ScenarioOp`, `ScenarioMessage`, `ScenarioBoard`, `GotScenarioBoardMessage`, поверхности телефона и почты), строка `ScenarioTypes` в `kinds/types.ts`, `'scenario'` в `BoardKindId` и третья ветка `withLesson`.

### D2. Документ, операции и цели

```ts
ScenarioDoc = {
  scene: Blank | Frame { id, art, spots } | Gallery { frames } | Trap { url, brand } | Letter { id, address, time }
  maybePhone: Option<{ owner, networks, vpn, draft, maybeJoined, isPortalPassed, isVpnOn, isSent }>
  maybeInbox: Option<{ owner, domain, mails, marks, followed }>
  mistakes: Array<GaveAwayPassword { ssid } | OpenedMailWithoutVpn | FollowedBait { mail }>
}
```

- **Операции автора:** `ShowScene` (кадр, галерея, страница-двойник, письмо), `SetUpPhone`, `SetUpInbox`. **Ходы ученика:** `JoinNetwork`, `PassPortal`, `GiveAwayPassword`, `LeaveNetwork`, `SetVpn`, `OpenMailWithoutVpn`, `SendMail`, `MarkMail`, `FollowLink`. Всё — Schema, журнал хранит их в `KindOp.ScenarioOp`. Доска на шаге N — свёртка, как у других видов.
- **Отказы** — коды без текста: `NetworkLocked`, `NetworkUnknown`, `Offline`, `VpnOff`, `MailUnknown`, `NoPhone`, `NoInbox`.
- **Цели:** `Online { ssid }` (подключён и прошёл страницу входа сети), `VpnOn`, `MailSent`, `PhishFlagged` (все приманки помечены), `RealKept` (все настоящие письма помечены настоящими). Невыполненная цель — код (`NotOnNetwork`, `VpnOff`, `MailNotSent`, `PhishLeft { count }`, `RealMisflagged { count }`).
- **`run` = сам документ:** считать нечего.

### D3. Ошибки записываются и объясняются, но не держат задачу

Пароль на странице сети-двойника, почта без VPN и нажатая ссылка в приманке — ходы, которые документ принимает и записывает в `mistakes`. Экран сразу объясняет ошибку (лист «Стоп: пароль ушёл соседу», красная плашка в почте, «картонная» страница по ссылке), телефон отключается от двойника, и задача решается дальше. Итог решённой задачи (`outcome` контракта) перечисляет ошибки этой задачи или пишет, что их не было.

Отклонено: цель «в приманках ничего не нажато» — после клика её нельзя выполнить без отмены, а отмена хода «я ввёл пароль» учит не тому. Поэтому у вида нет кнопок отмены, повтора и сброса (их ставит в приборы вид, `instruments` здесь пустой); «Показать решение» по-прежнему проигрывает эталон с чистого листа.

### D4. Кадр и всё текстовое поверх него

Кадр — `ShowScene(Frame { id, art, spots })`: `art` — адрес картинки, которую `lesson.ts` импортирует из `art/` урока (Vite отдаёт адрес с хешем), `spots` — что есть на кадре и на что можно сослаться: герои, предметы, табличка. Всё текстовое — элементы сцены шага `Annotate { key, caption }`:

| `caption` | Что рисует | Цель (`targets`) |
|---|---|---|
| `Narration` | плашка рассказчика | — |
| `Bubble { who, x, y, w, tail, tone }` | реплика или мысль героя | `who` |
| `Tag { spot, x, y, color }` | подпись предмета; подсвечивается от `[[spot|…]]` | `spot` |
| `Sign { ssid, x, y }` | табличка, которую можно открыть крупно | `sign` |
| `Zoom { x, y, w, tail }` | лупа на адресе, `**…**` — красная пометка | — |
| `Alt` | альт-текст картинки | — |
| `Thumb { frame }` | подпись миниатюры в галерее итога | `frame` |

Координаты — проценты кадра 4:3, размер шрифта — от ширины кадра (container units). Ключ подписи — литерал, поэтому `LessonTexts` требует текст каждой подписи на каждом языке без правки общих типов текстов; функция подписи получает документ, и реплика может зависеть от хода задачи (Марина в аэропорту). Имена героев, тексты писем, страниц сетей и договора — `labels` урока (`{ name, note }`), их тоже требует тип. Тест контента вида: у каждого кадра есть `Alt`, говорящий в реплике есть на кадре.

Отклонено: свой раздел `frames` в `LessonTexts` — общий тип текстов получил бы раздел одного вида.

### D5. Показ слайдами

Контракт получает необязательное `presentation: 'board' | 'slides'`; у `scenario` — `'slides'`. Подписи у нижнего края кадра отсчитываются снизу (`{ x, bottom }`), чтобы на узком экране, где шрифт крупнее кадра, они не уходили за край. Плеер ставит класс `slides` странице урока. На широком экране всё как у других курсов: прошлые шаги приглушены над текущим, кадр справа. На узком (≤ 880 px) кадр стоит над текстом, поэтому прошлые шаги скрыты, а после смены шага одна команда прокручивает новый шаг в колонке теории и затем страницу — к началу доски: ученик видит новый кадр, текст — сразу под ним. Реплики появляются вместе с кадром короткой CSS-задержкой; таймеров, автоперелистывания и «Смотреть» нет.

### D6. Экраны — поверхности вида в облике экранов курса сетей

`phone:<владелец>` и `mail:<владелец>` — `SurfaceDefinition<ScenarioTypes>` со своими Model и Message в `SurfaceState` и `SurfaceMessage`. Плеер даёт им вкладку, «Показать решение», журнал и призрак третьей подсказки (обводится место первого ещё не сделанного хода эталона). Своё состояние поверхности — только навигация и открытые листы; сеть, VPN, отправка, пометки и ошибки берутся из документа, поэтому «Показать решение» показывает на экране ровно журнал.

Облик и части — у телефона курса сетей: классы `device`, `screen-head`, `screen-networks`, `screen-network`, `screen-sheet`, `screen-button`, значки `lockIcon`, `wifiIcon`, `signalIcon`, строки `ui.device` (вкладка, «нет сети», «Открытая сеть, без пароля», «Защищена паролем», сила сигнала, «Понятно»). Сами поверхности `wifi:` и `browser:` курса сетей не подходят: они построены на `NetOp`, топологии и проверке пароля сети, а страницы входа в сеть и VPN-профиля там нет.

Раскладка: на широком экране телефон стоит справа от кадра (CSS `:has()` по корню доски вида); когда сцена шага пустая (почта), поверхность занимает всю правую часть. Без поддержки `:has()` поверхность встаёт под кадром, как у курса сетей.

### D7. Квиз «нажмите место на экране» (`PickHotspot`)

Новый вид квиза в `QuizKind`; его умеет только `scenario`. Кандидаты — места сцены: у страницы-двойника `skip` и `login`, у письма `name`, `addr`, `subj`, `btn`, `sign`; `resolveTarget` знает их по сцене, поэтому тест контента проверяет кандидатов как обычно. В режиме `Pick` места обведены пунктиром и доступны с клавиатуры (это кнопки); выбор уходит плееру `PickedTarget`. После попытки верное место зеленеет, выбранное неверное краснеет, рядом — метки `tags` квиза; у страницы-двойника метка выбранного исхода — штамп «Это был фишинг».

### D8. Страница-двойник: введённое никуда не попадает

Поля почты и пароля — обычные `input type="text"`, у пароля маска через CSS, `autocomplete="off"`, `data-1p-ignore`, `data-lpignore`; элемента `form` нет, и браузер не предлагает сохранить пароль. Обработчик ввода превращает значение в «поле не пустое» прямо в виде: сообщение доски `UpdatedTrapField { field, isFilled }` — единственное, что уходит в `update`. В Model доски — только два флага и какое поле подсветить. «Войти» с пустым полем показывает подсказку, как настоящая страница; с заполненными — `PickedTarget('login')`. Команд нет. После выбора страницу рисует другая функция вида, поэтому DOM полей создаётся заново пустым. Бренд — «Gooogle», адрес на `.example`, логотипов нет. Таймер «приз сгорит через …» — часть приманки: тикает в `frame` доски, ничего не листает.

Тест: сцена урока 5, ученик вводит адрес и пароль и нажимает «Войти»; обёртка `update` записывает каждое сообщение и каждую модель — ни в одном нет введённого текста, команд нет, поля после выбора пустые.

### D9. Слова вида в карточках

Карточка задачи говорит «Задача на доске», карточка квиза — «Нажмите ответ на доске», строка у закрытой «Далее» — «Решите задачу на доске». Для курса безопасности это неверно, поэтому контракт получает `taskHeading(ui)`, `pickHowTo(ui)` и `solveFirst(ui)` рядом с уже существующим `taskHowTo(ui)`; `flow` и `packet` возвращают прежние строки.

### D10. Тексты: интерфейс и урок

- Хром экранов (настройки телефона, страница входа в сеть, почта, страница-двойник, листы, коды сообщений, ошибки) — раздел `ui.scenario` словарей на четырёх языках.
- Содержимое урока (реплики, имена, письма, договор, тексты сетей) — `text.<язык>.ts` урока.
- Правило английских терминов в мягкой форме: Wi-Fi, VPN, 2FA и названия продуктов (1Password, Chrome, Claude) остаются как их видят люди; интерфейс экранов — на языке ученика, как на их телефонах; новое слово урока один раз выделено и объяснено. Обращение на «вы». Компании и домены — вымышленные, зона `.example`.

### D11. Курс, программа, элементы интерфейса

`courses/security/course.ts`: `board: 'scenario'`, `order: 3`, модули `access`, `people`, `tools`, `finale`, `features: SecurityFeature.literals`. Элементы: `phone.wifi`, `phone.vpn`, `phone.mail`, `quiz.choice` (урок 1), `mail.inbox`, `mail.linkPreview`, `quiz.pickHotspot` (урок 5). Поверхность телефона видна при любом `phone.*`, почта — при `mail.*`; VPN, приложение «Почта» и адрес ссылки в строке состояния спрашивают свои элементы. Остальные десять уроков — `meta.ts` с `available: false` и названия на четырёх языках: карта курса показывает программу целиком.

## Risks / Trade-offs

- [Подписи на кадре в процентах налезают друг на друга на 390 px] → шрифт от ширины кадра с нижним пределом, проверка в браузере на 390 px в обеих темах.
- [`-webkit-text-security` не везде прячет пароль] → на учебной странице это допустимо: значение всё равно никуда не уходит; отмечено в коде.
- [Антифишинговые фильтры примут страницу-двойник за настоящую] → нет настоящего бренда и логотипа, домен `.example`, нет формы и запросов.
- [Имена героев повторяются в `labels` каждого урока] → мелкое дублирование ради типовой проверки; общий словарь героев можно вынести позже без смены формата уроков.
- [Ошибки без отмены] → «Показать решение» и решение заново дальше работают; в итоге задачи ошибка названа, а не наказана.
