## Purpose

Аккаунты учеников: регистрация и вход по почте с паролем или через Google, подтверждение почты, сброс пароля, язык аккаунта и удаление аккаунта. Без входа курс доступен полностью, аккаунт нужен, чтобы прогресс сохранялся между устройствами.

## ADDED Requirements

### Requirement: Курс доступен без аккаунта

Все страницы курса SHALL открываться без входа. Приложение MUST NOT принудительно перенаправлять на вход и показывать блокирующие окна с предложением зарегистрироваться.

#### Scenario: Гость открывает урок

- **WHEN** человек без аккаунта открывает `/uk/lessons/load-balancer`
- **THEN** страница урока открывается, а в шапке есть ссылка «Увійти»

### Requirement: Регистрация по почте и паролю

Посетитель SHALL иметь возможность зарегистрироваться с именем, почтой и паролем не короче 10 символов. После регистрации на почту MUST уйти письмо со ссылкой подтверждения на языке страницы, где шла регистрация. Пока почта не подтверждена, вход по паролю MUST NOT создавать сессию. Если на сервере не настроена отправка почты, форма регистрации по почте SHALL быть недоступна, а вход через Google — доступен, если он настроен.

#### Scenario: Успешная регистрация

- **WHEN** посетитель на `/lt/sign-up` вводит имя, почту и пароль из 12 символов
- **THEN** показывается сообщение на литовском «проверьте почту», и на указанный адрес уходит письмо на литовском

#### Scenario: Почта уже занята

- **WHEN** посетитель регистрируется на адрес, у которого уже есть аккаунт
- **THEN** показывается то же сообщение «проверьте почту», что и при успешной регистрации, и по ответу нельзя понять, существует ли аккаунт

#### Scenario: Короткий пароль

- **WHEN** посетитель вводит пароль из 6 символов
- **THEN** форма показывает ошибку о минимальной длине на языке страницы, и аккаунт не создаётся

#### Scenario: Почта на сервере не настроена

- **WHEN** в окружении сервера нет настроек SMTP
- **THEN** на странице регистрации нет формы с паролем, а есть только вход через Google (если он настроен) с пояснением

### Requirement: Подтверждение почты

Переход по ссылке из письма SHALL подтверждать почту, сразу выполнять вход и открывать карту курса на языке аккаунта. Просроченная или уже использованная ссылка MUST показывать понятную ошибку с кнопкой повторной отправки письма.

#### Scenario: Подтверждение и вход

- **WHEN** пользователь переходит по свежей ссылке из письма
- **THEN** он оказывается на `/{язык аккаунта}/` уже вошедшим

#### Scenario: Просроченная ссылка

- **WHEN** пользователь переходит по ссылке старше 24 часов
- **THEN** показывается сообщение о просроченной ссылке и кнопка «отправить снова»

### Requirement: Вход по почте и паролю

Пользователь с подтверждённой почтой SHALL входить по почте и паролю. Неверная пара MUST давать одно общее сообщение, не раскрывающее, существует ли адрес. Для неподтверждённой почты MUST показываться сообщение с кнопкой повторной отправки письма. После 10 неудачных попыток в минуту с одного IP-адреса новые попытки MUST отклоняться с сообщением подождать.

#### Scenario: Неверный пароль

- **WHEN** пользователь вводит неверный пароль
- **THEN** показывается «Неверная почта или пароль» на языке страницы

#### Scenario: Подбор пароля

- **WHEN** с одного адреса приходит 11-я попытка входа за минуту
- **THEN** она отклоняется с сообщением подождать, а попытки с других адресов не блокируются

### Requirement: Вход через Google

Если на сервере заданы ключи Google, на страницах входа и регистрации SHALL быть кнопка «Войти через Google». Без ключей кнопки MUST NOT быть. Новый пользователь Google получает аккаунт. Если аккаунт с той же подтверждённой почтой уже есть, вход через Google MUST открывать этот же аккаунт, а не создавать второй. Отмена входа на стороне Google возвращает на страницу входа с сообщением.

#### Scenario: Привязка по почте

- **WHEN** пользователь с подтверждённым аккаунтом `a@example.com` входит через Google с той же почтой
- **THEN** он оказывается в своём аккаунте, и у аккаунта два способа входа: пароль и Google

#### Scenario: Ключи не заданы

- **WHEN** на сервере нет `GOOGLE_CLIENT_ID`
- **THEN** кнопки Google нет ни на одной странице, остальное работает

### Requirement: Сброс пароля

Пользователь SHALL иметь возможность запросить ссылку для сброса пароля. Ответ на запрос MUST быть одинаковым для существующих и несуществующих адресов. После задания нового пароля по ссылке пользователь MUST сразу оказаться вошедшим, а остальные его сессии MUST завершиться. Ссылка действует 1 час и только один раз.

#### Scenario: Новый пароль и сразу внутри

- **WHEN** пользователь открывает ссылку из письма и задаёт новый пароль
- **THEN** он попадает на карту курса уже вошедшим, а сессия на другом устройстве завершена

#### Scenario: Повторное использование ссылки

- **WHEN** ту же ссылку открывают второй раз
- **THEN** показывается сообщение, что ссылка недействительна, с предложением запросить новую

### Requirement: Выход

Вошедший пользователь SHALL иметь возможность выйти из меню аккаунта. После выхода сессия на этом устройстве недействительна, а интерфейс показывает состояние гостя без перезагрузки.

#### Scenario: Выход

- **WHEN** пользователь нажимает «Выйти»
- **THEN** шапка показывает ссылку на вход, а запрос сессии к серверу возвращает «не вошёл»

### Requirement: Состояние входа в интерфейсе

При загрузке приложение SHALL узнавать у сервера, вошёл ли пользователь. Вошедшему шапка показывает имя и меню (аккаунт, выход). Состояние MUST сохраняться после перезагрузки страницы, пока сессия действительна. Истёкшая сессия приводит к состоянию гостя без ошибок на экране.

#### Scenario: Перезагрузка страницы

- **WHEN** вошедший пользователь перезагружает страницу урока
- **THEN** шапка снова показывает его имя без повторного входа

### Requirement: Язык аккаунта

Язык страницы при регистрации SHALL сохраняться как язык аккаунта. Когда вошедший пользователь переключает язык, язык аккаунта MUST обновляться. Письма MUST приходить на языке аккаунта. После входа на новом устройстве со страницы без языкового префикса приложение открывается на языке аккаунта.

#### Scenario: Письмо на языке аккаунта

- **WHEN** пользователь с языком аккаунта `uk` запрашивает сброс пароля со страницы `/en/forgot-password`
- **THEN** письмо приходит на украинском

### Requirement: Страница аккаунта и удаление

Страница `/{язык}/account` SHALL показывать вошедшему пользователю его почту, имя, подключённые способы входа и язык аккаунта. С неё пользователь MUST иметь возможность удалить аккаунт после явного подтверждения. Удаление стирает пользователя, его сессии, способы входа и все связанные данные. Гостя страница отправляет на вход.

#### Scenario: Удаление аккаунта

- **WHEN** пользователь подтверждает удаление аккаунта
- **THEN** он оказывается гостем на карте курса, а вход с прежними данными больше невозможен

### Requirement: Безопасность сессий

Cookie сессии SHALL быть `HttpOnly`, `SameSite=Lax` и `Secure` при работе по HTTPS. В проде сервер MUST NOT запускаться без секрета сессий длиной не меньше 32 символов. Перенаправления после входа MUST вести только на адреса своего сайта.

#### Scenario: Нет секрета

- **WHEN** сервер в проде запускается без `BETTER_AUTH_SECRET`
- **THEN** процесс завершается при старте с сообщением, называющим переменную

#### Scenario: Чужой адрес возврата

- **WHEN** запрос на вход передаёт адрес возврата `https://evil.example/`
- **THEN** сервер отклоняет запрос, и перехода на чужой сайт нет
