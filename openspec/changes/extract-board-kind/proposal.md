## Why

Курс «Сети для вайбкодеров» живёт на той же платформе, но его доска — не схема потоков, а сеть с пакетами (план `docs/plans/networks-course.md`, разделы 3.1–3.4, 4.2, 4.4, 4.5). Сейчас плеер, DSL урока, журнал, подсказки и тесты контента зашиты на доску System Design: `BoardOp`, `simulate`, цели потоков, приборы. Это изменение — пункт 3 раздела 4.6 плана: без общего контракта вида доски нельзя начать доску сетей (`add-network-board`) и поверхности задач (`add-terminal-and-browser`, `add-settings-panel`).

## What Changes

- **Контракт вида доски `BoardKind`.** Документ и операции со свёрткой и отказом-кодом, расчёт (`run`), проверка целей, цели ссылок и подсветок, строки журнала, тексты кодов, подмодуль доски с приборами, поверхности задачи. Плеер, DSL, журнал, подсказки и тесты контента работают только через него.
- **System Design — вид `flow`.** Поведение и вид уроков System Design не меняются: те же шаги, доска, приборы, журнал, подсказки, «Показать решение», «было → стало».
- **Вид `packet` — заготовка на модели пакетов** (`src/net/`): документ — мир сети, свёртка `NetOp` вместе с `send`, цели модели пакетов, тексты кодов на четырёх языках, элементы сцены `play`, `pauseAt`, `openEnvelope`, `showTable`. Доска — простой список устройств; настоящую доску делает `add-network-board`.
- **Поверхности задачи.** Задача объявляет `surfaces: ['board', 'wifi:phone', …]`. Поверхность — подмодуль Foldkit; её ходы попадают в журнал задачи, поэтому отмена, повтор, сброс, проверка и «Показать решение» работают без изменений. Вкладки поверхностей видны только в шаге задачи и только если курс их открыл (`unlocks`). Для проверки механизма — простейшая поверхность «Wi-Fi устройства»: сети, пароль, «Подключиться».
- **Урок объявляет вид:** `defineLesson(flow, { slug, steps })`. Тексты по-прежнему проверяются типами по `lesson.ts`.
- **Тексты урока для сетей:**
  - ссылки `[[id|…]]` с `:` (`[[link:router-internet|кабель]]`, `[[env:tcp|TCP]]`, `[[zone:kitchen|кухня]]`), их смысл решает вид доски;
  - раздел `labels` — подписи сущностей доски по языкам; урок перечисляет их в `labels` своего `lesson.ts`;
  - раздел `feedback` — свой текст урока для кода сообщения в задаче.
- **BREAKING для авторов уроков:** `defineLesson` принимает вид доски первым аргументом, операции System Design импортируются из `kinds/flow/dsl`. Тринадцать уроков System Design переведены.

## Capabilities

### New Capabilities

- `board-kind`: контракт вида доски, виды `flow` и `packet`, поверхности задачи, тесты контента через контракт.

### Modified Capabilities

- `lesson-player`: ссылки в тексте шага указывают не только на блоки; урок может давать подписям доски свои названия и свои тексты типичных ошибок.

## Impact

- **Код `apps/web`:** новая папка `src/kinds/` (контракт, union хранения, виды `flow` и `packet`, поверхность Wi-Fi); обобщены `lesson/dsl.ts`, `lesson/player.ts`, `lesson/view.ts`, `lesson/course.ts`, `courses/registry.ts`, `courses/content.test.ts`; приборы System Design переехали в `kinds/flow/view.ts`; `lesson.ts` тринадцати уроков; словари интерфейса (вкладки поверхностей, доска сетей, Wi-Fi) на четырёх языках; стили поверхностей.
- **Model плеера:** доска — union `BoardState` (`FlowBoard | PacketBoard`), ходы задачи — union `KindOp`, коды — `KindMessage`, поверхности — `SurfaceState`. Итог «было → стало» считается при показе, а не хранится.
- **Модель пакетов (`src/net/`)** не меняется: вид `packet` пользуется её миром (`applyWorld`), целями и текстами `NetMessage` из `extend-packet-model`.
- **Документация:** `AGENTS.md`, `apps/web/AGENTS.md`, `CONTRIBUTING.md`.
