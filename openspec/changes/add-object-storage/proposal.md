## Why

Почти любая система хранит файлы: картинки товаров, аватары, видео, вложения, бэкапы, результаты фоновых задач. В реальных архитектурах они живут не в базе данных, а в **object storage** (по-русски — объектное хранилище): пользователь загружает файл напрямую по presigned URL, CDN берёт из хранилища то, чего у неё нет в кеше, а фоновый worker кладёт туда результаты. На доске потоков такого блока нет, поэтому уроки про медиа, загрузки и CDN перед файлами нельзя собрать.

## What Changes

- **Новый вид блока `storage`** с подписью «Object storage»: ранг 7 (конец потока, как база), ёмкость 50 000 rps, 0,05 $ в час, id `storage-1`, `storage-2`, …, своя иконка (ведро), места по умолчанию в правой колонке доски, родное объяснение `kindHint` на uk, ru, en, lt по правилу английских названий.
- **Новые связи:** Users → Object storage (загрузка по presigned URL), CDN → Object storage (origin для промахов), Worker → Object storage (результат задачи). Остальные связи с хранилищем отклоняются с прежними пояснениями; из хранилища поток дальше не идёт.
- **Поведение в потоке:** хранилище держит поток в пределах ёмкости, как база, и теряет лишнее. Для запросов пользователей (напрямую или промахами CDN) оно строит план задержки: путь до него, в том числе переход между регионами, плюс постоянные 40 мс (`simulationRules.storageMs`). Поэтому промахи CDN входят в p95.
- **Worker** кладёт в свои хранилища по одному объекту на задачу, отдельно от записей в базы (`writesPerJob`).
- Цели `HasKind`, `MaxUtilization`, `Carries`, `SurvivesFailure` и прочие работают с новым видом без изменений; медленный p95 может подсветить хранилище как самый загруженный блок пути.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `system-board`: новый блок Object storage на доске и в палитре, его связи.
- `traffic-simulation`: Object storage в потоке и во времени ответа.

## Impact

- **Код:** `apps/web/src/domain/catalog.ts` (вид, подпись, связи), `domain/board.ts` (id), `domain/simulate.ts` (обработчики хранилища и worker, `storageMs`), `domain/goals.ts` (путь задержки), `board/board.ts` (места палитры), `board/view.ts` (иконка), `i18n/ui/*` (`kindHint`).
- **Уроки 1–13** блок не используют; их снимки симулятора не меняются, а палитра «Позже в курсе» строится только из палитр уроков.
- **Документация:** `CONTRIBUTING.md` — блок `storage`, его связи и как моделировать загрузки отдельной группой пользователей.
- **Вне объёма:** байты и полоса, размер объектов, счётчики по ключам, связь сервера с хранилищем.
