## Purpose

HTTP-сервер приложения: один процесс раздаёт собранное веб-приложение и служебные API-маршруты, настраивается через переменные окружения и корректно останавливается при перезапуске.

## ADDED Requirements

### Requirement: Раздача веб-приложения

Сервер SHALL отдавать HTML веб-приложения на любой GET-запрос вне `/api/` и вне статических файлов, чтобы прямые ссылки на языковые страницы открывались. Файлы с хешем в имени MUST отдаваться с долгим кешированием (`immutable`), а HTML — без кеширования.

#### Scenario: Прямая ссылка на урок

- **WHEN** браузер запрашивает `/lt/lessons/load-balancer`
- **THEN** сервер отвечает 200 с HTML приложения и заголовком, запрещающим кеширование

#### Scenario: Статический файл с хешем

- **WHEN** браузер запрашивает `/assets/index-3f2a9c.js`
- **THEN** сервер отвечает 200 с `Cache-Control`, содержащим `immutable`

### Requirement: Проверка здоровья

Сервер SHALL отвечать на `GET /api/health` статусом 200 и JSON с полями `status` (`"ok"`) и `version` (идентификатор собранной версии).

#### Scenario: Сервер работает

- **WHEN** выполняется `GET /api/health`
- **THEN** ответ 200 с телом `{"status":"ok","version":"<версия>"}`

### Requirement: Неизвестные API-маршруты

Запрос к неизвестному пути под `/api/` SHALL получать ответ 404 в формате JSON, а не HTML приложения.

#### Scenario: Опечатка в API

- **WHEN** выполняется `GET /api/no-such-endpoint`
- **THEN** ответ 404 с JSON-телом, содержащим поле `error`

### Requirement: Настройка через окружение

Сервер SHALL читать адрес и порт прослушивания и каталог веб-сборки из переменных окружения. По умолчанию он слушает только `127.0.0.1`. Если обязательная настройка отсутствует или некорректна, процесс MUST завершиться при старте с сообщением, в котором названа переменная.

#### Scenario: Некорректный порт

- **WHEN** сервер запускается с `PORT=abc`
- **THEN** процесс завершается с ненулевым кодом и сообщением, называющим `PORT`

### Requirement: Локальный запуск без настройки

После клонирования репозитория команды `pnpm install` и `pnpm dev` SHALL поднимать приложение и сервер без файла `.env` и без внешних сервисов. Секреты и внешние сервисы MUST требоваться только в режиме `production`.

#### Scenario: Первый запуск у контрибьютора

- **WHEN** разработчик клонирует репозиторий на чистую машину с Node 24+ и pnpm и выполняет `pnpm install && pnpm dev`
- **THEN** приложение открывается в браузере, `/api/health` отвечает 200, и ни одна переменная окружения не потребовалась

### Requirement: Корректная остановка

По сигналу SIGTERM сервер SHALL перестать принимать новые соединения, дождаться завершения начатых запросов (не дольше 10 секунд) и завершить процесс с кодом 0.

#### Scenario: Перезапуск во время запроса

- **WHEN** сервер получает SIGTERM во время обработки запроса
- **THEN** начатый запрос получает полный ответ, после чего процесс завершается
