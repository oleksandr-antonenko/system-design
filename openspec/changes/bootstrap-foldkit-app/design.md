## Context

Репозиторий пуст. Мотивация — в proposal.md. Ограничения, которые определяют решения:

- Владелец проекта выбрал `effect@4.1.0` (вышел 2026-10-29). Foldkit 0.169 и пакеты `@foldkit/*` заявляют peer `effect@4.0.0`; самый свежий canary — `4.0.0||4.0.6`. Официальной поддержки 4.1 у Foldkit пока нет (см. D0).
- Соглашения Foldkit (`FOLDKIT.md` из `create-foldkit-app@0.40.0`): Model только из Schema, Message — факты в прошедшем времени, эффекты только через Commands, `defineRouteUnion`, `Option` вместо `null`, без `switch`, `for` и `let`-итераций.
- Следующие изменения добавят на тот же сервер better-auth и SQLite и выкатку на домашний сервер владельца. Каркас должен принять их без перестройки.
- Репозиторий публичный: разработчики клонируют его, запускают локально без какой-либо настройки и присылают уроки через PR. Уроки — самостоятельные модули; добавление урока не должно требовать правок в общем коде.
- Языки: `uk`, `ru`, `en`, `lt`. Литовский пишется латиницей с диакритикой (ą č ę ė į š ų ū ž), украинский — кириллицей с ґ є і ї.

## Goals / Non-Goals

**Goals:**

- Структура workspace, в которую дальше без переделок встанут доска, симулятор, плеер уроков, вход и прогресс.
- Механизм локализации, при котором пропущенный перевод невозможно выкатить.
- Один процесс сервера, который в проде отдаёт и web, и `/api`.

**Non-Goals:**

- Предрендер страниц (SSG) и `hreflang` в `<head>` — отдельное изменение `add-static-prerender`. Языковой префикс в URL уже делает его простым.
- Ручной переключатель темы. Пока только системная настройка.
- Содержимое уроков, доска и симулятор — следующие изменения по `docs/roadmap.md`.

## Decisions

### D0. Effect 4.1.0 поверх Foldkit, объявленного под 4.0.0

В корневом `package.json` задаются `pnpm.overrides` (`effect`, `@effect/platform-browser`, `@effect/platform-node` → `4.1.0`) и `pnpm.peerDependencyRules.allowedVersions`. Так в дереве остаётся ровно одна копия `effect`, общая для Foldkit и нашего кода: две копии сломали бы Schema и сервисы. По semver 4.1 обратно совместима с 4.0. Однако Foldkit пользуется модулями `effect/unstable/*`, которые под semver не попадают.

Поэтому первая задача — смоук-проверка: установка, `tsc`, Story- и Scene-тесты примера и запуск dev-сервера с рабочим роутингом. Если проверка не проходит, это блокер: о нём сообщается владельцу с конкретной ошибкой. Дальше два пути: временно откатиться на `4.0.6` (её уже допускает canary Foldkit) или чинить через `patchedDependencies`. Выбор за владельцем.

- *Альтернатива:* `effect@4.0.0`, как требует Foldkit. Отклонена решением владельца.

**Результат смоук-проверки (2026-10-29).**

- Рантайм Foldkit, Story- и Scene-тесты и роутинг работают на 4.1.0 без изменений.
- Сломался только `@foldkit/vite-plugin@0.28.0`: в 4.1 `Crypto` больше не экспортируется из корня `effect`, а плагин брал его для id и токена DevTools-релея.
- Исправлено патчем `patches/@foldkit__vite-plugin@0.28.0.patch` через `patchedDependencies`: две функции переведены на `node:crypto`.
- Патч удаляется, когда Foldkit выпустит плагин с поддержкой 4.1. Если обновлённый плагин не совпадёт с патчем, pnpm напомнит об этом ошибкой установки.

### D1. pnpm workspace: `apps/web` и `apps/server`

Web и сервер — отдельные пакеты со своими `package.json`, общий lock-файл и корневые скрипты (`check`, `build`, `dev`). Общие Schema-контракты между клиентом и сервером появятся в `packages/contracts`, когда возникнет первый общий тип (вход и прогресс). Сейчас этот пакет не создаётся.

- *Альтернатива:* один пакет с `src/client` и `src/server`. Отклонена: разные окружения тестов (happy-dom и node), разные tsconfig и риск случайно утащить серверный код в бандл.

### D2. Web — SPA из шаблона `create-foldkit-app` (режим `spa`)

Шаблон генерируется во временном каталоге (`--rendering spa --example routing --package-manager pnpm`), из него берутся конфиги (`vite`, `vitest`, `.oxlintrc*`, `.oxfmtrc`, `tsconfig`, `FOLDKIT.md`, `AGENTS.md`, `.mcp.json`) и переносятся в `apps/web`. Пример `routing` служит образцом маршрутов и удаляется.

- *Альтернатива:* сразу SSG. Отложена: SSG требует серверного entry и дисциплины гидрации. Пользы до появления контента мало, а языковой префикс уже совместим с SSG.

### D3. Язык — часть маршрута

`AppRoute` объявляется через `defineRouteUnion`: `Home { locale }`, `Lesson { locale, slug }`, `NotFound { locale, path }`. Парсер читает первый сегмент как `Locale`. Если он не является языком, init отправляет Command `ReplaceUrl` на `/{выбранный язык}{исходный путь}` (требование «Ссылка без префикса»). Смена языка — обычная навигация по ссылке `<a href="/en/...">`: Foldkit перехватывает клик через `routing.onUrlRequest`, ссылки открываются в новой вкладке и видны поисковикам.

Язык не хранится в Model отдельно от маршрута: `localeOf(route)` — единственный источник. Это убирает расхождение «URL на одном языке, интерфейс на другом».

### D4. Определение и запоминание языка

При загрузке в Runtime передаются Flags `{ savedLocale: Option<string>, browserLanguages: Array<string> }`: значение из `localStorage` по ключу `sd.locale` и `navigator.languages`. Чистая функция `resolveLocale(flags)` реализует порядок «сохранённый → браузер по основному подтегу → `en`» и покрывается таблицей тестов. После каждой смены маршрута, если язык отличается от сохранённого, update возвращает Command `SaveLocale` (запись в `localStorage`, ошибки глотаются в `CompletedSaveLocale`).

- *Альтернатива:* cookie. Нужна только при SSR; до него `localStorage` проще. При входе пользователя (изменение `add-user-accounts`) язык дополнительно сохраняется в профиль.

### D5. Словари интерфейса — типизированные TS-модули

```
apps/web/src/i18n/
  locale.ts       Locale = Schema.Literals(['uk','ru','en','lt']), resolveLocale, названия языков
  plural.ts       plural(locale, n, forms) на Intl.PluralRules; формы типизированы по языку
  format.ts       formatNumber(locale, n) на кешированных Intl.NumberFormat
  ui/types.ts     UiStrings — тип словаря: строки и функции (count, params) => string
  ui/uk.ts ru.ts en.ts lt.ts   export const uk = { ... } satisfies UiStrings
  ui/index.ts     uiFor(locale): UiStrings
```

`satisfies UiStrings` даёт ошибку tsc и на пропущенный, и на лишний ключ. Тест `i18n.test.ts` дополнительно проверяет, что строки непустые и что функции множественного числа дают правильные формы для 0, 1, 2, 5, 11, 21, 22 и 1.5 на каждом языке. Типы форм заданы по языку: для `ru` и `uk` нужны `one | few | many`, для `lt` — `one | few | many | other`, для `en` — `one | other`. Забыть форму нельзя.

Во view язык берётся из маршрута, а словарь — через `uiFor(localeOf(model.route))`. Это чистый поиск, без состояния в Model.

- *Альтернатива:* i18next или FormatJS (ICU-строки). Отклонена: ключи и параметры проверяются только во время работы, плюс рантайм-парсер в бандле.
- *Альтернатива:* Paraglide (компилирует сообщения в типизированные функции). Хороший кандидат, если появятся переводчики без доступа к коду: у него есть редактор inlang. Пока переводит разработчик, обычный TS проще и не требует отдельного шага генерации. Переход возможен позже, ключи переносятся механически.

### D6. Доменные сообщения — коды и параметры

Доменные функции возвращают значения вида `Schema.TaggedStruct`, например `LbFansOutTooFew { have: 2, need: 3 }`. Тексты для них лежат в словарях как функции от параметров: `messages.LbFansOutTooFew({ have, need })`. Покрытие всех кодов проверяет тип `Record<DomainMessage['_tag'], ...>`. В этом изменении механизм вводится и покрывается тестом на одном служебном коде. Массово он заработает в изменении проверки задач.

### D7. Уроки — самостоятельные модули, тексты по языкам

Урок — каталог `apps/web/src/lessons/<NN>-<slug>/`:

- `meta.ts` — `slug`, место в курсе (модуль и порядок), признак `available`, список языков, на которых урок написан;
- `text.<locale>.ts` — название, описание и (в следующих изменениях) все тексты урока на этом языке;
- позже `lesson.ts` — структура шагов и задач.

Реестр уроков собирается автоматически через `import.meta.glob('./lessons/*/meta.ts', { eager: true })`. Новый урок — это новая папка, без правок в общих файлах, поэтому PR от разных авторов не конфликтуют. Тест реестра проверяет уникальность `slug` и порядковых номеров.

В этом изменении создаются 13 папок только с `meta.ts` и `text.*.ts` (название и описание на всех четырёх языках). Это карта курса и образец для контрибьюторов.

Переводы: урок объявляет языки, на которых написан, и для каждого объявленного языка тексты обязаны быть полными. Если урока нет на языке страницы, он показывается на запасном языке (английский, иначе первый объявленный) с заметной пометкой. Интерфейс вокруг остаётся на языке страницы. Так можно принять урок от автора, который пишет на одном языке, а переводы добавить отдельными PR.

### D7a. Локальный запуск без настройки

`pnpm install && pnpm dev` поднимает web и сервер без `.env`: у всех настроек есть значения для разработки, SQLite-файл создаётся в `apps/server/.data/` (в `.gitignore`), письма печатаются в консоль, Google выключен. Обязательные секреты требуются только при `NODE_ENV=production`.

### D8. Шрифты и темы

Шрифты из макета (Unbounded, Literata, JetBrains Mono) подключаются через `@fontsource` или `@fontsource-variable` с подмножествами `latin`, `latin-ext`, `cyrillic`, `cyrillic-ext`, без внешнего CDN. Цветовые токены макета переносятся в CSS-переменные со светлыми значениями по умолчанию и тёмными под `prefers-color-scheme: dark`, а затем пробрасываются в Tailwind v4 через `@theme`.

### D9. Сервер — Effect HTTP на `@effect/platform-node`

`apps/server` — `NodeRuntime.runMain` с HTTP-роутером Effect:

- `GET /api/health` возвращает `{ status, version }`, где `version` берётся из `APP_VERSION` (выкатка ставит короткий хеш коммита);
- `/api/*` без совпадения отвечает JSON 404;
- статика из `WEB_DIST` отдаётся с `immutable` для `/assets/*`;
- для остальных путей отдаётся `index.html` с `Cache-Control: no-cache`.

Конфигурация читается через `Config` (`PORT` по умолчанию 3620, `HOST` по умолчанию `127.0.0.1`, `WEB_DIST`, `APP_VERSION`). Корректную остановку обеспечивают `NodeRuntime.runMain` и scope сервера: прерывание по SIGTERM закрывает listener и ждёт текущие запросы. Точные имена модулей HTTP в Effect 4 (`effect/unstable/http` против `@effect/platform`) сверяются по установленным типам при реализации.

В dev-режиме Vite проксирует `/api` на сервер (`server.proxy`). В браузере один origin и в dev, и в проде, поэтому cookie сессий в следующем изменении работают без CORS.

- *Альтернатива:* Hono. Его связка с better-auth проверена в других проектах владельца, но вторая парадигма рядом с Effect не нужна. Hono остаётся запасным вариантом, если мост better-auth ↔ Effect HTTP окажется хрупким.
- *Альтернатива:* `@foldkit/node` `serve`. Это хост для SSR-рендера, понадобится в `add-static-prerender`.

### D10. Тесты

Корневой `vitest.workspace` объединяет проекты `web` (happy-dom, Story и Scene, тесты i18n) и `server` (node). Серверные тесты поднимают HTTP-слой на свободном порту и ходят в него `fetch`. Все запуски идут в тихом режиме (`vitest run --silent --reporter=dot`), `pnpm check` = `tsc --noEmit` по пакетам + `oxlint` + тесты.

## Risks / Trade-offs

- [Foldkit не объявлял поддержку `effect@4.1.0`, а модули `effect/unstable/*` могли измениться] → Смоук-проверка первой задачей (D0). Порядок действий при поломке описан там же.
- [Бета Foldkit и свежий Effect 4 ломают API в минорных версиях] → Версии без `^`, обновление отдельным изменением. Доменный код (i18n, позже граф и симулятор) не импортирует Foldkit.
- [Переводы на `uk` и `lt` пишет не носитель] → Тексты интерфейса короткие. Перед публикацией первых уроков носитель вычитывает переводы, это задача в изменении с уроками.
- [Шрифты с четырьмя подмножествами увеличивают вес] → `font-display: swap`, браузер грузит подмножества по `unicode-range` лениво, каждая страница тянет только нужные.
- [Дубли страниц на четырёх языках без `hreflang`] → Пока сайт рендерится на клиенте, индексируется плохо. `hreflang` и предрендер появятся в `add-static-prerender`.
- [Мост better-auth ↔ Effect HTTP в следующем изменении] → Сервер с первого дня строится на web-совместимых Request/Response. Если мост не сложится, роутер меняется на Hono без влияния на web.
