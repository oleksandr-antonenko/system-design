## Context

Мотивация — в proposal.md. Изменение строится на контракте вида доски из `extract-board-kind`: задача объявляет `surfaces`, поверхность — `SurfaceDefinition<T>` со своим подмодулем Foldkit, её ходы (`SurfaceOutMessage.ProducedOps`) плеер дописывает в журнал задачи, `SurfaceContext.maybeGhost` несёт эталон после третьей подсказки. Модель пакетов (`src/net/`) уже даёт всё нужное: `runCommand` (вывод, подсказка-код, операции, трассы, `running`), `browse` (страница или код ошибки браузера с причиной), `checkJoin` и `nearbyNetworks` для Wi-Fi, `hostIface` для сведений о сети, `loginBanner` и вход по ssh, операции `JoinWifi`, `ForgetWifi`, `SetDns`, `SetAddressing`, `RunCommand`, `Send`. Доску сетей рисует `add-network-board`; панели настроек — `add-settings-panel`.

## Goals / Non-Goals

**Goals:**

- Ходы на устройствах ничем не отличаются от ходов на доске: журнал, отмена, повтор, сброс, «Проверить», «Показать решение».
- Поверхность ничего не помнит о сети сама: что она показывает, выводится из документа и истории операций.
- Вывод команд и коды ошибок — как в жизни, без перевода; объяснения — на языке интерфейса.
- Урок 6 работает целиком ещё до того, как доска нарисует «двери» портов.

**Non-Goals:**

- Вид доски (двери портов, петля у устройства, конверт «адрес:порт») — `add-network-board`.
- Переключатель вывода macOS / Linux / Windows — `add-terminal-os-flavors`.
- Настоящее выключение Wi-Fi на телефоне: в модели нет такой операции, переключатель показывает «включено».
- Уроки, кроме 6: здесь только их поверхности и элементы курса.

## Decisions

### D1. Всё, что видно, — из истории операций

`SurfaceContext.history` — операции, из которых свёрнут `doc`: шаги урока до текущего и журнал задачи (`stepOps`). Поверхность сворачивает их сама (`momentsOf`: мир до и после каждой операции, отказанная пропускается, как на доске):

- терминал устройства — команды `RunCommand` этого устройства, каждая посчитана `runCommand` на мире до неё с открытыми уроком командами;
- браузер — последний `Send(Browse|Submit)` с устройства, посчитанный `browse` на мире до хода.

Поэтому «Показать решение» печатает в терминале ровно то, что напечатал бы ученик, отмена стирает строку, а команда шага 2 урока 6 (`run('laptop', 'npm run dev')`) видна в терминале задачи. Model поверхности хранит только то, чего нет в сети: набираемую строку, историю ↑/↓, ответ на невыполненную строку, открытое приложение, страницу настроек, черновики DNS и адреса.

Альтернатива — копить вывод в Model поверхности. Отвергнута: «Показать решение» и отмена идут мимо поверхности, вывод разошёлся бы с журналом.

### D2. Что становится ходом

- Терминал: строка, у которой `runCommand` дал вывод или операции, — ход `run(device, line)`. Неизвестная или ещё закрытая команда, команда с одной подсказкой (`CommandUsage`) — не ход: ответ терминала живёт в Model (`Notice`). Иначе `applyWorld` (он выполняет `RunCommand` со всеми командами) сделал бы то, что ученик не мог. Пока программа держит терминал (`running`), строка — тоже не ход, а ответ «сервер ещё работает». Ctrl+C — ход `run(device, 'Ctrl+C')` только когда программа работает.
- Wi-Fi: своя сеть с неверным паролем — ход (`JoinWifi`: телефон пробует и не подключается, причина видна в «Моя сеть» и у цели); чужая сеть (соседа, кафе) — не ход, только объяснение `checkJoin`: в документе до неё нет радиосвязи. Своя открытая сеть подключается сразу.
- DNS «Автоматически» — сразу ход `setDns(auto)`; «Вручную» — черновик списка и «Сохранить». Адрес вручную — черновик и «Сохранить» (`setStatic` или `useDhcp`); отказ модели (`GatewayOutsideSubnet`, `InvalidIp`) плеер показывает тостом.
- Браузер: «Открыть» и «Обновить» — `send(Browse)` с адресом в каноническом виде (`http://` добавлен, `http://192.168.1.42:5173/`), форма входа — `send(Submit)`.

### D3. Один экран устройства

`wifi:<d>` и `browser:<d>` — два определения с одним подмодулем `ScreenSurface` и `screen: 'device'`. Плеер оставляет из поверхностей одного экрана и устройства первую объявленную (`visibleSurfaces`): одна вкладка «Экран · Телефон», открытая на её приложении. Переключатель приложений виден, только если задача объявила оба (`SurfaceContext.surfaces`) и курс их открыл. Урок 3 пишет `surfaces: ['board', 'browser:phone', 'wifi:phone']`, чтобы экран открывался на браузере. Вид экрана — по виду хоста: телефон (вырез, строка состояния, «док» снизу) или окно компьютера (заголовок с вкладками приложений).

### D4. Открыто ли (план 3.4)

Скрыто, а не заблокировано. Поверхность видна по префиксу (`wifi.*`, `browser.*`, `terminal.*`); внутри:

| Элемент курса | Что открывает |
|---|---|
| `wifi.join` | список сетей, пароль |
| `wifi.networkInfo` | «Сведения о сети», «Настроить DNS», «Забыть эту сеть» |
| `wifi.addressing` (урок 8) | «Настройка адреса», строка «Маска» |
| `browser.page` | страница |
| `browser.addressBar` | адресная строка (только чтение), «Обновить», коды без своего элемента |
| `browser.typeAddress` | ввод адреса |
| `browser.errNameNotResolved`, `…ConnectionRefused`, `…ConnectionTimedOut`, `browser.errCert` | код ошибки на экране |
| `browser.certificate` | замок и сертификат, «Не защищено» |
| `browser.form` (урок 11) | форма входа на странице `/login` |
| `terminal.ipAddr`, `ipRoute`, `ping`, `arp`, `npmRunDev`, `traceroute`, `nslookup`, `dig`, `curl`, `ss`, `nc`, `ufw`, `docker`, `tunnel` | команда и кнопка-подсказка |
| `board.deviceMac` / `terminal.traceroute` | MAC в `ip a` / `ttl=` в `ping` |
| `terminal.freeInput` (урок 15) | без кнопок-подсказок |
| `board.sandbox` (урок 16) | все команды, включая `certbot` |

Код ошибки, которую курс ещё не открыл, не показывается: экран с заголовком и строкой «почему». Кнопка-подсказка открытой в уроке команды несёт метку «новое».

### D5. Экран ошибки браузера

Заголовок и строка — как в браузере на языке интерфейса («Не удаётся получить доступ к сайту», «Сайт localhost не позволяет установить соединение.»), код — как есть (`ERR_CONNECTION_REFUSED`), ниже строка «Почему: …» — текст кода модели (`NetMessage`) через `SurfaceSlot.renderMessage`, то есть с `feedback` урока, если он есть. У `NET::ERR_CERT_*` «почему» спрятано за «Дополнительные», как в Chrome. Сценарии уроков 3 и 11 требуют заголовок на языке интерфейса; переводится только он и строка, код — никогда.

Картинки вариантов `Choice` (урок 6) — те же экраны в миниатюре: ключ `screenPicture(code | 'page', url)`, рисует `BoardKind.picture` вида `packet`.

### D6. Терминал

- Тонкий вид над `runCommand`. Открытые команды — `terminalFeatures(unlocked)` по таблице D4.
- `transcriptOf` даёт записи `Command`, а для сервера (`kind: 'server'`, ssh с компьютера ученика — `laptop` или первый ноутбук/ПК) ещё `Login` (баннер `loginBanner`, первый вход и новый после восстановления) и `Disconnected` (ход закрыл ssh: `client_loop: send disconnect: Broken pipe`). Терминал сервера без ssh — «Консоль хостинга»: вкладка переименована, команды работают как раньше. Ход, закрывший вход, может прийти из любой поверхности (панель файрвола).
- `clear` прячет записи до текущей (в Model), `exit` ничего не делает.
- Призрак — следующая по порядку команда устройства из эталона, которой ещё нет в журнале: серый текст в строке ввода; если это Ctrl+C — пунктир у кнопки «Ctrl+C».
- Клавиши: ↑/↓ — история, Ctrl+C — прерывание (`OnKeyDownPreventDefault` в строке ввода; глобальные клавиши плеера в полях ввода не срабатывают). Прокрутка держится у последней строки через `column-reverse`, без команд.

### D7. Ход со своей сценой

`BoardKind.moveStage(before, op)` — сцена хода ученика: у `packet` — `play(intent)` для `Send` и трассы команды терминала для `RunCommand`. Плеер показывает доске сцену последнего хода задачи, если она есть (`boardStage`), иначе сцену шага, и `BoardContext.stageDoc` — документ до хода, чтобы трасса считалась на том мире, где ход сделан (у справочной ещё нет ответа в памяти). При новом ходе со сценой (руками или «Показать решение») плеер вызывает `BoardHost.replay` — доска проигрывает трассу с начала. У `flow` сцены хода нет. Заготовка доски `packet` считает трассы на `stageDoc`; настоящая доска (`add-network-board`) обязана делать так же.

### D8. Тексты

Раздел `device` словарей интерфейса (`i18n/ui/device/<язык>.ts`, тип `DeviceStrings`) — отдельными файлами, чтобы правки разных поверхностей не сталкивались в общих словарях. Неиспользуемые строки `network.wifi*` проверочной поверхности убраны.

## Risks / Trade-offs

- [Поверхность пересчитывает историю при каждой отрисовке] → Уроки короткие (десятки операций); плеер и так сворачивает документ с нуля. Если станет медленно — кэш по ссылке на документ.
- [У сервера проверка ssh — трасса на каждую операцию истории] → Только у терминала сервера (уроки 12–16).
- [Призрак терминала знает только команды эталона] → Урок 12 решает задачу панелью файрвола, а призрак в терминале сервера хочет команду `ufw`; нужен способ задать призрак отдельно от эталона (вопрос владельцу).
- [Ctrl+C у `tunnel http` не закрывает туннель] → В модели Ctrl+C снимает только слушателя 5173; нужен `tunnelDown` в действии Ctrl+C (просьба к модели пакетов).
- [Карточка задачи показывает подсказку System Design «перетащите блок из палитры»] → Текст `howTo` плеера общий для всех видов; его стоит брать у вида (вопрос к `add-network-board`).
