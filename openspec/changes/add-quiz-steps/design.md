## Context

Мотивация — в proposal.md. Изменение строится на контракте вида доски из `extract-board-kind` (`BoardKind`, `BoardContext.maybeQuiz`, режим доски `Pick`, `BoardOutMessage.PickedTarget`). Модель пакетов уже даёт помощники ответов квизов (`net/answers.ts`: `dhcpServerOf`, `nextHopAfter`, `lastReplyOf`, `deathDeviceOf`, `sourceAddressSeenBy`…). Сценарии уроков сетей (`docs/plans/networks-lessons/`) задают виды квизов, метки на доске, картинки вариантов и тексты «Подробнее» и «Как спросить ИИ».

## Goals / Non-Goals

**Goals:**

- Общая карточка вопроса и правила попытки для любого вида доски.
- `Choice` и `PickDevice` работают на доске System Design; доска сетей добавляет остальные виды без правок плеера.
- Тексты квиза проверяются типами по `lesson.ts`, содержание — тестами контента.

**Non-Goals:**

- `NextHop`, `PickLinks`, `PickLayer`, `PlaceChips`, `SpotFault`, картинки вариантов (экраны браузера) — `add-network-board`.
- Сохранение результата «с первой попытки» между сессиями.

## Decisions

### D1. Квиз в шаге урока

```ts
quiz: {
  id: 'db-after-cache',
  kind: 'Choice',               // или 'PickDevice', 'NextHop', …
  candidates: ['unchanged', 'all-reads', 'writes-and-misses', 'misses'],
  answer: 'writes-and-misses',  // или (doc, run) => string — считает движок
  pictures: { refused: 'browser:ERR_CONNECTION_REFUSED' }, // Choice, по желанию
  hideUntilAnswered: ['load'],  // подсказка виду доски, по желанию
}
```

- `quiz` и `task` в одном шаге запрещены тестом контента (не типом: union шагов ломал вывод типов задач).
- Ответ-функция `(doc, run) => string` получает доску шага; помощники `net/answers.ts` превращаются в неё одной строкой. Так автор не ошибается в ответе, где его знает движок.
- Кандидаты — строки, их понимает `resolveTarget` вида: устройство, блок, `link:…`, `env:…`, или id варианта `Choice`.

### D2. Состояние и сообщения плеера

- `Model.quizzes: Record<id квиза, { picked, isCorrect }>`: отсутствие — нет попытки. Попытка одна, поэтому `isCorrect` — это и «с первой попытки».
- `ClickedChoice { candidate }` — выбор в карточке; выбор на доске приходит из подмодуля доски как `PickedTarget(id)`. Оба идут в `answerQuiz`: шаг с квизом, попытки не было, кандидат из списка — иначе ничего.
- `maxAllowedStep` останавливается на первом шаге с нерешённой задачей или неотвеченным квизом; поэтому «Далее», шкала, клавиши и ссылка `?step=N` ведут себя как у задачи.
- Режим доски: `Pick`, пока у шага квиз на доске без ответа. Кандидаты передаются подмодулю доски (`BoardInput.pickable`).

Альтернатива — хранить попытки списком. Отклонена: правило одной попытки проще выразить отсутствием или наличием ответа.

### D3. Тексты

`LessonTexts` получает раздел `quizzes` только если в уроке есть квизы:

```ts
quizzes: {
  'db-after-cache': {
    question: '…',
    explain: '…',                    // разметка шага: **…**, [[…]], списки
    options: { unchanged: '…', … },   // только у Choice, обязательно для всех кандидатов
    wrong: { misses: '…' },          // по желанию: почему неверно
    tags: { db: '…' },               // по желанию: короткая метка на доске
  },
}
```

Тексты шага: `steps[id].more?: { title, body }` и `askAi?: { lead, template, note? }` на уровне урока (показывается на последнем шаге). Наличие этих блоков одинаково во всех языках проверяет тест контента.

### D4. Вид доски и квизы

Контракт вида получает:

- `quizzes: ReadonlyArray<QuizKind>` — какие квизы на доске он умеет (`Choice` рисует карточка);
- `picture(key, ui, h) → Option<Html>` — картинка варианта `Choice`;
- `targetName(doc, target, ui)` — как назвать кандидата в карточке, если урок не дал подписи.

`BoardContext.maybeQuiz` (`BoardQuiz`): кандидаты, выбор, ответ (только после попытки), метки, что прятать (только до ответа). Доска System Design:

- кандидаты — `role=button`, `tabindex=0`, Enter и пробел выбирают (`PressedPickKey`); нажатие мышью — `ReleasedPointer` на блоке;
- выбранный неверно — класс `pick-wrong` (вспышка, без анимации при уменьшенном движении), ответ — `pick-right`, метки рядом с блоками;
- `hideUntilAnswered: ['load']` или id блока — подпись нагрузки «скрыта до ответа», без полосы загрузки и подписей потоков на связях.

### D5. Разметка: списки

`parseBlocks` делит абзац на строки: строки до первой `- ` — абзац, строки с `- ` — пункты, строка без `- ` после пункта продолжает его. `parseProse` (только абзацы) остаётся для прежних тестов; ссылки ищутся по блокам.

### D6. Копирование шаблона

Кнопка «Скопировать» шлёт `ClickedCopyAskAi { template }`; команда `CopyAskAiTemplate` пишет в буфер обмена (`navigator.clipboard`) и возвращает `CompletedCopyAskAiTemplate { isCopied }`; ошибка не роняет приложение. Пометка «Скопировано» сбрасывается при смене шага.

### D7. Квиз в System Design

Один квиз, где он помогает: в уроке «Кеширование» на шаге «Чтение и запись», перед задачей. `Choice`: сколько запросов дойдёт до базы при 1600 rps с кешем (запись 320 + промахи 256 = 576). Числа в текстах считаются из правил симуляции, итог задачи показывает то же число. Урок «Балансировщик» не тронут: его шаги покрыты тестами навигации.

## Risks / Trade-offs

- [Клик по палитре System Design в браузере не добавляет блок, перетаскивание добавляет] → Было так и до изменения (проверено на опубликованной версии): `setPointerCapture` перенаправляет `click`. Отдельная задача.
- [Квиз угадывается перебором] → Попытка одна, кандидатов 2–5.
- [Скрытое до ответа состояние вида] → Подсказка (`hideUntilAnswered`) толкуется видом; неизвестные ключи игнорируются.
