## Purpose

Путь кода от коммита до `https://system-design.oleksandr-antonenko.com` для публичного репозитория: проверки любого PR без доступа к серверу, автоматическая выкатка проверенного `main` с откатом при сбое, HTTPS, изоляция приложения на сервере и сохранность данных.

## ADDED Requirements

### Requirement: Проверки на pull request

Каждый pull request, в том числе из форка, SHALL автоматически проходить проверки: соответствие lock-файла, типы, линтер, тесты и сборку. Проверки MUST выполняться на машинах GitHub, без доступа к серверу и без секретов. Для PR от внешних авторов запуск MUST требовать одобрения владельца.

#### Scenario: PR из форка с падающим тестом

- **WHEN** внешний автор открывает PR из форка, владелец одобряет запуск, и в PR падает тест
- **THEN** проверка в PR красная, а прод и сервер никак не затронуты

#### Scenario: PR пытается изменить workflow

- **WHEN** PR из форка меняет файл workflow, чтобы получить секреты или доступ к серверу
- **THEN** у запуска нет секретов доступа к серверу и прав на запись в репозиторий

### Requirement: Автоматическая выкатка проверенного main

После push в `main` с зелёными проверками ветка `production` SHALL указывать на этот коммит, а сервер MUST сам выкатить его. Тот же запуск в Actions MUST дождаться, пока `https://system-design.oleksandr-antonenko.com/api/health` ответит версией этого коммита, и показать успех или ошибку.

#### Scenario: Успешная выкатка

- **WHEN** в `main` попадает коммит `abc1234`, и проверки зелёные
- **THEN** не позже чем через 10 минут `/api/health` отвечает `"version":"abc1234"`, и запуск в Actions зелёный

### Requirement: Откат при неудачной выкатке

Если новая версия не ответила на `/api/health` своей версией за 60 секунд после запуска, сервер SHALL вернуть предыдущую версию. Неудачный коммит MUST NOT собираться повторно, пока `production` не сменится. Запуск в Actions MUST завершиться ошибкой по тайм-ауту проверки версии.

#### Scenario: Версия не стартует

- **WHEN** выкатываемая версия падает при запуске
- **THEN** сайт продолжает отвечать предыдущей версией, сервер не пытается собрать тот же коммит снова, а запуск в Actions красный

### Requirement: Ручной откат

Владелец SHALL иметь возможность откатить прод, переставив ветку `production` на прежний коммит. Если версия этого коммита ещё хранится на сервере, переключение MUST выполняться без пересборки.

#### Scenario: Откат на прошлую версию

- **WHEN** владелец переставляет `production` на коммит, выкаченный ранее
- **THEN** в течение минуты `/api/health` отвечает версией этого коммита

### Requirement: Выкатки по очереди

Две выкатки на сервере SHALL NOT выполняться одновременно. Если `production` сменилась во время выкатки, следующая выкатка начинается после окончания текущей и берёт последнее значение ветки.

#### Scenario: Два коммита подряд

- **WHEN** в `main` подряд попадают два коммита
- **THEN** в итоге работает второй коммит, и выкатки не пересекались

### Requirement: HTTPS

Сайт SHALL быть доступен по `https://system-design.oleksandr-antonenko.com` с действующим сертификатом, который продлевается автоматически. Запросы по HTTP MUST перенаправляться на HTTPS с тем же путём.

#### Scenario: Вход по HTTP

- **WHEN** браузер открывает `http://system-design.oleksandr-antonenko.com/uk/`
- **THEN** ответ 301 на `https://system-design.oleksandr-antonenko.com/uk/`

### Requirement: Секреты и инфраструктура вне репозитория

Секреты приложения (ключ сессий, ключи Google, SMTP) SHALL храниться только в `.env` на сервере. В репозитории и в настройках GitHub MUST NOT быть секретов доступа к серверу, а в файлах репозитория — адреса и ssh-порта сервера, имён пользователей и учётных данных. Если `.env` на сервере отсутствует, выкатка MUST остановиться до переключения версии.

#### Scenario: Нет файла окружения

- **WHEN** на сервере нет `.env` приложения
- **THEN** выкатка завершается ошибкой «нет .env», работающая версия не меняется

### Requirement: Изоляция приложения на сервере

Приложение, его данные и процесс выкатки SHALL работать под отдельным пользователем сервера без прав администратора. Компрометация приложения или выкатываемого кода MUST NOT давать доступ к другим проектам на сервере и к правам root.

#### Scenario: Попытка повысить права

- **WHEN** процесс приложения пытается выполнить `sudo`
- **THEN** операция отклоняется, у пользователя приложения нет прав sudo

### Requirement: Данные переживают выкатку

SQLite-базы SHALL лежать вне каталогов версий и сохраняться между выкатками. Перед каждым переключением версии MUST создаваться согласованная резервная копия каждой базы. Хранятся последние 10 копий.

#### Scenario: Резервная копия перед выкаткой

- **WHEN** выкатывается новая версия, а в каталоге данных есть `app.db`
- **THEN** появляется копия с датой и коммитом, а самых старых копий сверх 10 нет
