## Why

Каждое следующее изменение должно само оказываться на `https://system-design.oleksandr-antonenko.com` — без ручных шагов и с откатом при сбое. Репозиторий публичный и принимает PR от сторонних авторов. Поэтому привычная схема со своим раннером GitHub Actions на сервере не подходит: код из чужого PR мог бы выполниться на домашнем сервере, где работают и другие проекты владельца.

## What Changes

- Проверки: workflow на GitHub-hosted раннерах (`ubuntu-latest`) для каждого PR, включая PR из форков, и для `main`. В него входят lock-файл, `pnpm check` и `pnpm build`. Секретов у workflow нет.
- Продвижение: после зелёных проверок на `main` workflow переставляет ветку `production` на этот коммит, используя только встроенный `GITHUB_TOKEN`.
- Выкатка pull-based. Таймер systemd на сервере каждые 30 секунд читает `production` через `git ls-remote`. Если ветка указывает на новый коммит, `release.sh`:
  - собирает его рядом с работающей версией;
  - делает резервную копию SQLite;
  - переключает ссылку `current`, перезапускает службу и ждёт `/api/health` с нужной версией;
  - при сбое возвращает предыдущую версию и запоминает неудачный коммит, чтобы не пересобирать его по кругу.
- Подтверждение: job workflow опрашивает публичный `https://…/api/health`, пока не увидит версию своего коммита (до 10 минут). Результат выкатки виден в Actions.
- Откат вручную: владелец переставляет `production` на прежний коммит, сервер возвращает уже собранную версию за секунды.
- Изоляция на сервере: отдельный пользователь без sudo, под ним приложение, данные и таймер выкатки. nginx-хост с TLS от certbot и редиректом с HTTP.
- Настройки репозитория:
  - запуск workflow из PR внешних авторов только после одобрения владельца;
  - права `GITHUB_TOKEN` по умолчанию — только чтение;
  - ветка `production` защищена от удаления.

## Capabilities

### New Capabilities

- `deployment`: путь кода в прод — проверки PR, продвижение, pull-выкатка, откат, HTTPS, секреты и изоляция на сервере, сохранность данных.

### Modified Capabilities

(нет)

## Impact

- Новые файлы:
  - `.github/workflows/ci.yml`;
  - `deploy/release.sh`, `deploy/poll.sh`;
  - `deploy/system-design-web.service`, `deploy/system-design-deploy.{service,timer}`;
  - `deploy/nginx.conf`;
  - `deploy/README.md` — общая инструкция без адресов и имён.
- Сервер владельца (разовая настройка, детали вне репозитория):
  - пользователь приложения с linger;
  - каталог приложения и `.env`;
  - пользовательские службы;
  - nginx-хост и сертификат.
- Зависит от `bootstrap-foldkit-app`: нужны `pnpm build`, запуск сервера и `/api/health` с версией.
