## Context

Мотивация — в proposal.md. Изменение строится на контракте вида доски из `extract-board-kind`: задача объявляет `surfaces`, поверхность — `SurfaceDefinition<T>` со своим подмодулем Foldkit, её ходы (`SurfaceOutMessage.ProducedOps`) плеер дописывает в журнал задачи, а `SurfaceContext.maybeGhost` несёт эталон задачи после третьей подсказки. Модель пакетов (`src/net/`) уже знает все нужные операции (`ConfigureWifi`, `SetDhcpPool`, `ReserveAddress`, `Forward`, `AddRoute`, `SetRecord`, `Listen`, `SetRedirect`, `IssueCertificate`, `SetFirewall`, `UpdateVpn`, `JoinMesh`, `SetCompose`, `ComposeUp`) и коды отказов на четырёх языках (`net/text`). Доску сетей (план квартиры, кольца, проход телефона) рисует `add-network-board`.

## Goals / Non-Goals

**Goals:**

- Один компонент на все панели курса; новая панель — новое описание, без правок компонента и плеера.
- Ходы панели ничем не отличаются от ходов на доске: журнал, отмена, повтор, сброс, «Показать решение», проверка целей.
- Ошибки ввода объясняются словами модели (`NetMessage`) у того поля, где ошиблись.
- Урок 5 работает целиком (квиз, задача, цели, решение) ещё до того, как доска нарисует план квартиры.

**Non-Goals:**

- Вид доски: план, стены, кольца, полоски сигнала, проход устройства — `add-network-board`.
- Экран телефона, терминал и браузер — `add-terminal-and-browser`.
- Уроки 9–16 целиком: здесь только их панели и элементы курса.
- Порядок правил файрвола стрелками, «Изменить» по строке и отдельная форма «Добавить правило» из сценариев: список строк покрывает те же действия.

## Decisions

### D1. Панель — описание, компонент один

```ts
type PanelDefinition = {
  type: 'router' | 'dns-panel' | 'server' | 'vpn' | 'mesh' | 'compose'
  feature: string                     // префикс UiFeature поверхности
  device: (world, target) => Option<DeviceId>
  tabLabel, heading
  tabs: ReadonlyArray<{
    id, feature,                      // 'router.wifi' — вкладка видна, когда открыта
    label,
    fields: (context) => ReadonlyArray<Field>
    read: (context) => Values         // значения по документу
    save: (context, draft, base) => Check<ReadonlyArray<NetOp>>
    blame?: (message: NetMessage) => Option<path>
    saveLabel?                        // «Выпустить» вместо «Сохранить»
  }>
}
```

- Значения формы — строки: поле — строка, список — строки с ячейками и стабильным `id` (из модели: MAC, `proto:port`; новые — `new-N`). Так Model остаётся Schema, а схема полей — обычные функции вне Model.
- Поля зависят от документа (`fields(context)`): порты программ сервера, сервисы compose, устройства для закрепления адреса.
- Все панели хранятся в одном варианте `SurfaceState.PanelSurface` и `SurfaceMessage.GotPanelSurfaceMessage`: состояние у панелей одинаковое, различается описание. Поверхность `тип[:устройство]` находит описание по типу.

Альтернатива — подмодуль на каждую панель. Отклонена: шесть копий черновика, проверки и вида.

### D2. Черновик помнит, с чего начался

`Model.drafts[tab] = { base, values, problems }`. Черновик действителен, только пока `base` равен тому, что вкладка читает из документа сейчас. Отмена хода, сброс, «Показать решение», смена шага меняют документ — черновик устаревает сам, без сообщений от плеера, и панель показывает документ. Вне открытой задачи (`mode !== 'Edit'`) панель только показывает.

### D3. «Сохранить»: проверка, пробное применение, ходы

1. Нет изменений — нет ходов (кнопки «Сохранить» и «Отменить» недоступны).
2. `save` разбирает черновик: пустое поле — `Required`, не число — `NotANumber`, не адрес, не сеть, порт вне 1–65535 — коды модели `InvalidIp`, `InvalidCidr`, `InvalidPort`. Ошибки всех полей сразу, у своих ячеек.
3. Операции пробуются на документе (`applyPacketOp`) по порядку. Первый отказ — код модели (`WifiPasswordTooShort`, `ReservationOutsideSubnet`, `CnameAtApex`, `SplitTunnelEmpty`, `NoCertificateAuthority`…) у поля, которое назвал `blame`, иначе под формой.
4. Без отказов — `ProducedOps(ops)`, черновик удаляется, у кнопок «Сохранено».

Операции — только изменения: пул и закрепления сравниваются с роутером, правила проброса и маршруты — построчно, записи DNS — по группам «имя + тип» (одна запись — `setRecord`, несколько — `removeRecord` и `addRecord`), сервер — по каждой программе. Поэтому эталон задачи в уроке совпадает с тем, что пишет панель (`configureWifi` с тем же каналом, `vpnSettings` с тремя полями, `meshJoin` без имени, если имя — id устройства).

### D4. Призрак — разница с эталоном

Компонент применяет эталон к текущему документу и сравнивает чтение вкладки до и после: изменившиеся поля и списки получают пунктирную рамку и `aria-description` «Подсказка: посмотрите сюда», значения не подставляются. Вкладка с такими полями тоже обведена, чтобы ученик её нашёл. Поля только для чтения не обводятся.

### D5. Вкладки по unlocks и метка «новое»

Вкладка видна, если `SurfaceContext.unlocked` содержит её `feature`; поверхность — если открыт хоть один элемент её префикса (`isSurfaceOpen`). Метку «новое» вкладка получает из `newFeatures`. Выбранная вкладка, которой нет среди открытых, заменяется первой открытой.

Новые элементы курса: `server.site`, `server.cert` (урок 11), `server.firewall` (12, заменяет `router.firewall`: панели правил роутера ни один урок не просит, сценарий урока 12 предлагает именно эту замену), `compose.file` (14), `mesh.members` (16).

### D6. Раскладка и вид

Слева вертикальные вкладки (`role=tablist`, `aria-orientation=vertical`), справа форма (`role=tabpanel`, `<form>` — Enter сохраняет). Вид нейтральный: токены темы проекта, без логотипов и цветов производителей. На узком экране (≤ 880 px) вкладки — горизонтальная строка с прокруткой, поля во всю ширину, шрифт полей 16 px (iOS не увеличивает страницу), строки списков — карточки с подписью у каждой ячейки (`data-label`). Стили — `panel.css` рядом с компонентом, подключён одной строкой из `styles.css`.

### D7. Панели курса

| Поверхность | Вкладка (элемент) | Поля | «Сохранить» |
|---|---|---|---|
| `router[:id]` | Wi-Fi (`router.wifi`) | имя сети, пароль, «С паролем / Без пароля», диапазон 2,4 / 5 / оба; канал скрыт и подбирается к диапазону | `configureWifi` |
| | Устройства (`router.devices`) | таблица: устройство, адрес, MAC, подключение | — |
| | Адреса (`router.addresses`) | пул «с — по», закреплённые адреса: устройство (по MAC), адрес | `setDhcpPool`, `RemoveReservation`, `reserve` |
| | Порты (`router.ports`) | протокол, внешний порт, адрес в доме, внутренний порт | `unforward`, `forward` |
| | Маршруты (`router.routes`) | сеть, через роутер | `RemoveRoute`, `addRoute` |
| `dns-panel[:id]` | Записи (`dnsPanel.records`) | тип, имя, значение, TTL | `setRecord`, `removeRecord`, `addRecord` |
| `server:<id>` | Сайт (`server.site`) | доступ к каждой программе: закрыт / только сам сервер / открыт всем; перенаправление на https | `listen`, `stopListening`, `setRedirect` |
| | Сертификат (`server.cert`) | текущий сертификат, имена нового; кнопка «Выпустить» | `issueCert` |
| | Файрвол (`server.firewall`) | вкл/выкл, правила (откуда, порт, протокол, что делать), остальные входящие | `firewall` |
| `vpn:<id>` | VPN (`vpn.settings`) | подключение, весь трафик / рабочие сети, список сетей; шлюз, адрес, DNS — только чтение | `vpnSettings` |
| `mesh[:id]` | Устройства (`mesh.members`) | свои устройства: «В сети», имя, адрес (только чтение) | `meshJoin`, `meshLeave` |
| `compose:<id>` | compose.yaml (`compose.file`) | переменные и порты каждого сервиса; пояснение, если файл расходится с запущенным | `compose` |

- `router` без устройства — роутер `router` или первый роутер без VPN-сервера; `dns-panel` без устройства — самая длинная зона доски не у справочной; `mesh` без устройства — первый координатор (UDP 41641).
- «Расходится с запущенным» = `docker compose up` на этой доске изменил бы документ (`ComposeUp` пробуется и сравнивается).

### D8. Урок 5

Сцена и тексты — из `docs/plans/networks-lessons/05-wifi-range.md`; стены — операции модели `wall(…)`. Квиз `PickDevice` считает ответ по доске шага: кандидат, чья радиосвязь не подключается. Задача: `surfaces: ['board', 'router']`, цели `Associated(phone)`, `Associated(bulb)`, `WifiSecurity(router, wpa2)`, эталон `configureWifi('router', wifi('Router-7C21', '12345678', { band: 'dual' }))`; отзывы `feedback` на `OutOfRange`, `BandUnsupported`, `GoalWifiTooWeak`, `WrongSsid`, `WrongPassword`. Квиз шага 4 включает только 5 ГГц на канале 36: канал 6 из сценария для 5 ГГц модель отвергает (`InvalidChannel`).

## Risks / Trade-offs

- [Призрак по разнице чтений] → Обводится всё, что эталон меняет относительно текущей доски: если ученик уже что-то испортил, обведено и это. Это и нужно подсказке.
- [Список вместо «Изменить»/«Закрепить»/формы «Добавить правило» из сценариев] → Те же операции, меньше особых виджетов; если урок попросит особую форму, её можно добавить видом поля.
- [`mesh` угадывает «свои» устройства] → Компьютеры, телефоны и серверы без служебных ролей (справочная, DNS-провайдер, CA, ретранслятор). Урок 16 может потребовать явный список; тогда он станет параметром поверхности.
- [Тексты уроков вместо кодов в панели] → Ошибка у поля — текст модели (`net/text`); свой текст урока (`feedback`) панель пока не видит: `SurfaceContext` не несёт тексты урока. Карточка задачи показывает `feedback` как раньше.
- [Проход телефона, комнаты как цели ссылок, подсветка стен] → Нужны доске (`walk`, `room`, `zone:…`); урок 5 их пока не использует и получит их вместе с доской сетей.
