## 3. Шаги

### Шаг 1 · `apartments` · Квартиры в доме

> Адрес — номер дома. Но в доме много квартир, и почтальону нужен ещё номер квартиры. С компьютером так же: на нём работает много программ, и каждой нужны свои конверты. Номер программы называется **порт** — это номер квартиры.
>
> На [[shop|сервере магазина]] сайт живёт в квартире 443. Поэтому на конверте телефона теперь два числа через двоеточие: адрес и порт — 198.51.100.10:443. Нажмите «Пуск».

**Доска.** Операции — сборка из раздела 2. У `shop` и `dns` появляются «двери» с номерами (`443`, `80`; `53`), метка «новое» на двери 443. Карточка `shop` открывается сама на время шага. Сцена: `play(Browse(phone → https://shop.example/), { as: 'letters' })`. Конверт показывает адрес и порт: «от: 192.168.1.100:51514 · телефон», «кому: 198.51.100.10:443 · сайт магазина» (порт отправителя — из счётчика движка). Когда конверт доходит до сайта, дверь 443 подсвечивается.

- Подпись до «Пуск»: «Нажмите «Пуск»: конверт идёт в квартиру 443 сервера магазина.»
- После трассы: аннотация `door443` у `shop`, тон ok: «квартира 443: сайт».

### Шаг 2 · `dev-server` · Свой сайт на ноутбуке

> Вы с ИИ пишете свой сайт. Чтобы посмотреть, что получилось, в терминале ноутбука запускают `npm run dev`. Запускается dev-сервер — программа, которая показывает ваш сайт, пока вы его пишете. Он занимает квартиру 5173 и пишет, где его открыть: `http://localhost:5173`.
>
> **localhost** — имя, которое на любом устройстве значит «я сам». Как пометка «себе» на конверте: такой конверт никуда не уходит. На ноутбуке `localhost:5173` — это квартира 5173 самого ноутбука. Нажмите «Пуск»: браузер ноутбука откроет сайт.

**Доска.** Операция шага: `listen('laptop', 'tcp', '127.0.0.1', 5173)` — так `npm run dev` запускает сервер по умолчанию. У ноутбука появляется дверь `5173` с замком «только для своих». Рядом с доской распечатка `printout('laptop', 'npm run dev')` (открыта в уроке 4, `board.printout`):

```
$ npm run dev

  VITE ready in 312 ms

  ➜  Local:   http://localhost:5173/
  ➜  Network: use --host to expose
```

Сцена: `play(Browse(laptop → http://localhost:5173/), { as: 'letters' })` — конверт не выходит из ноутбука: делает петлю у самого устройства и входит в дверь 5173 (**нет в плане**: показ трассы без хопов, внутри устройства).

- Подпись до «Пуск»: «Нажмите «Пуск»: ноутбук откроет localhost:5173.»
- После трассы: аннотация `devOpened` у `laptop`, тон ok: «сайт открылся на ноутбуке».

Квиз `Choice`, раздел 4.

### Шаг 4 · `door` · Дверь открыта только изнутри

> Значит, телефону нужен настоящий адрес ноутбука — 192.168.1.42, из урока 2. Но и по адресу 192.168.1.42:5173 телефон получит отказ. Нажмите «Пуск».
>
> Dev-сервер по умолчанию открывает дверь только изнутри: заходить к нему может лишь сам ноутбук. Это ради безопасности: пока вы пишете сайт, соседям по Wi-Fi незачем его видеть. Чтобы впустить телефон, сервер запускают с флагом `--host` — «открой дверь для всех в домашней сети».

**Доска.** Операций нет (сервер по-прежнему на `127.0.0.1:5173`). Сцена: `play(Browse(phone → http://192.168.1.42:5173/), { as: 'letters' })` — конверт «кому: 192.168.1.42:5173 · ноутбук» доходит до ноутбука, упирается в дверь 5173 с замком и возвращается отказом (`ListensOnlyOnLoopback`).

- Подпись до «Пуск»: «Нажмите «Пуск»: телефон постучится в квартиру 5173 ноутбука.»
- После трассы: аннотация `onlyInside` у `laptop`, тон bad: «5173 открыт только для своих».

Здесь же блок «Подробнее» (раздел 7).

|---|---|

| После попытки | сцена проигрывает `play(Browse(phone → http://localhost:5173/), { as: 'letters' })`: конверт делает петлю у телефона, у телефона нет двери 5173, конверт возвращается отказом; аннотация `phoneEmpty` у `phone`, тон bad: «на телефоне в 5173 пусто» |

| id | Экран | Подпись варианта |
|---|---|---|
| `page` | страница «Мой сайт» | «Ваш сайт открылся» |
| `refused` | «Не удаётся получить доступ к сайту. Сайт localhost не позволяет установить соединение.» и код `ERR_CONNECTION_REFUSED` | «Отказ в соединении» |
| `not-found` | «Не удаётся найти сайт» и код `ERR_NAME_NOT_RESOLVED` | «Сайт не найден» |
| `offline` | «Нет подключения к интернету» и код `ERR_INTERNET_DISCONNECTED` | «Нет интернета» |

Неверные ответы (`wrong`):

| Вариант | Объяснение |
|---|---|
| `page` | «Сайт живёт на ноутбуке, а `localhost` на телефоне значит сам телефон. Телефон стучится в свою же квартиру 5173 — а там никого.» |
| `not-found` | «Имя `localhost` телефон знает без всякой справочной: оно всегда значит «я сам». Адрес он нашёл — это он сам. Ошибка будет другой.» |
| `offline` | «Wi-Fi у телефона есть, а интернет здесь ни при чём: конверт даже не выходит из телефона.» |

Общее объяснение (`explain`): «`localhost` — это всегда «я сам». На телефоне это сам телефон, а в его квартире 5173 никто не живёт. Телефон стучится — дверь закрыта. Это и есть ERR_CONNECTION_REFUSED: «в соединении отказано».»

## 5. Задача · шаг `phone-dev`

**Что сломано в начале.** Dev-сервер слушает только `127.0.0.1:5173` (из шага 2). Браузер телефона открыт на `localhost:5173` с ошибкой `ERR_CONNECTION_REFUSED`. Операций шага нет.

**Поверхности:** `['board', 'terminal:laptop', 'browser:phone']`. Терминал и экран телефона рядом с доской (на телефоне — вкладками под доской).

**Терминал ноутбука** (вывод не переводится; упрощённый, как в Unix). В начале в нём история шага 2, сервер работает:

```
$ npm run dev

  VITE ready in 312 ms

  ➜  Local:   http://localhost:5173/
  ➜  Network: use --host to expose
```

Пока сервер работает, строка ввода показывает на языке интерфейса: «Сервер работает в этом окне. Ctrl+C — остановить», и рядом кнопка «Ctrl+C» (**нет в плане**: процесс, который занимает терминал, и Ctrl+C). Кнопки-подсказки под строкой: `Ctrl+C`, `npm run dev`, `ip a`.

| Ввод | Вывод | Операция |
|---|---|---|
| Ctrl+C (кнопка или клавиши) | `^C` и приглашение `$` | `stopListening('laptop', 'tcp', 5173)` |
| `npm run dev` | вывод как выше | `listen('laptop', 'tcp', '127.0.0.1', 5173)` |
| `npm run dev -- --host` (и `npm run dev -- --host 0.0.0.0`) | см. ниже | `listen('laptop', 'tcp', '0.0.0.0', 5173)` |
| `npm run dev --host` (без `--` посередине) | как у `npm run dev`: npm забирает флаг себе, сервер его не получает | `listen('laptop', 'tcp', '127.0.0.1', 5173)` |
| `ip a`, `ipconfig` | см. ниже | — |
| другая команда | подсказка на языке интерфейса: «Доступные команды: npm run dev, ip a, ping.» | — |
| любая команда, пока сервер работает | подсказка: «Сервер ещё работает в этом окне и занимает его. Остановите его: Ctrl+C.» | — |

```
$ npm run dev -- --host

  VITE ready in 298 ms

  ➜  Local:   http://localhost:5173/
  ➜  Network: http://192.168.1.42:5173/
```

Адрес в строке `Network` берётся из адреса ноутбука в движке.

```
$ ip a
lo0: inet 127.0.0.1/8
en0: inet 192.168.1.42/24
```

MAC (`ether`) в выводе `ip a` нет до урока 7.

**Браузер телефона:** адресная строка редактируется; ввод без `http://` дополняется до `http://` (как в настоящем браузере; **нет в плане**). «Открыть» порождает `send(Intent.Browse({ from: 'phone', url }))`, трасса проигрывается на доске. Удача — страница «Мой сайт» (заголовок «Мой сайт», строка «Эту страницу показывает dev-сервер с вашего ноутбука»). Отказ — экран `ERR_CONNECTION_REFUSED` из квиза, с адресом из строки.

**Цели:**

| id | Текст цели (`goals`) | Проверка |
|---|---|---|
| `listens` | Сервер открыт для домашней сети | `Goal.Listening({ device: 'laptop', proto: 'tcp', port: 5173, maybeBind: Option.some('0.0.0.0') })` (есть) |
| `phone-opens` | Сайт открылся на телефоне | `Goal.Performed({ intent: Browse, from: 'phone', deliveredAt: 'laptop', port: 5173 })` — ученик открыл адрес на телефоне, и конверт вошёл в квартиру 5173 ноутбука (**нет в плане**, как в уроке 2) |

**Текст карточки задачи:**

- `prompt`: «Откройте свой dev-сервер с телефона.»
- `solvedNote`: «Сайт с ноутбука открылся на телефоне. Это и есть главное обещание курса: теперь вы знаете, почему localhost не работает с телефона и что с этим делать.»

**Подсказки:**

1. «По адресу localhost телефон стучится сам к себе. Ему нужен адрес ноутбука. А серверу — разрешение пускать гостей из домашней сети.»
2. «Остановите сервер: Ctrl+C. Запустите снова с флагом: npm run dev -- --host. Два минуса посередине важны: так флаг достанется серверу, а не npm.»
3. «В строке Network сервер сам напишет адрес для телефона: http://192.168.1.42:5173. Наберите его в браузере телефона.» Призрак: в строке терминала серая подсказка `npm run dev -- --host`; пунктирная рамка вокруг адресной строки телефона (без значения).

**Решение (операции):**

```ts
run('laptop', 'Ctrl+C'),                 // stopListening('laptop', 'tcp', 5173)
run('laptop', 'npm run dev -- --host'),  // listen('laptop', 'tcp', '0.0.0.0', 5173)
send(Intent.Browse({ from: 'phone', url: 'http://192.168.1.42:5173/' })),
```

После решения доска проигрывает конверт «телефон → роутер → ноутбук» в квартиру 5173: замок с двери снят, дверь открывается; экран телефона показывает «Мой сайт». Аннотация `devOnPhone` у `phone`, тон ok: «ваш сайт на телефоне».

| Действие | Что видно | Текст |
|---|---|---|
| Набрать команду, не остановив сервер | подсказка терминала | (см. таблицу терминала) |
| `npm run dev --host` | в строке Network по-прежнему `use --host to expose` | «npm забрал флаг себе, и сервер его не получил: в строке Network всё ещё «use --host». Нужны два минуса: npm run dev -- --host.» |
| Телефон: `localhost:5173` | `ERR_CONNECTION_REFUSED` | «localhost на телефоне — это сам телефон. Нужен адрес ноутбука.» |
| Телефон: `192.168.1.42:5173` до `--host` | `ERR_CONNECTION_REFUSED` (`ListensOnlyOnLoopback`) | «Адрес верный, но дверь сервера пока открыта только для самого ноутбука. Перезапустите сервер с --host.» |

| Телефон: `192.168.1.100:5173` | отказ на самом телефоне | «Это адрес самого телефона. Нужен адрес ноутбука — он в строке Network или в выводе ip a.» |
| Телефон: `https://192.168.1.42:5173` | в жизни — `ERR_SSL_PROTOCOL_ERROR` (**нет в движке**, раздел 8) | «Dev-сервер работает без шифрования: адрес начинается с http://, а не https://.» |
| Телефон: `192.168.1.42:5174` или другой порт | `ERR_CONNECTION_REFUSED` | «В этой квартире никто не живёт. Dev-сервер — в квартире 5173.» |

## 6. Итог · шаг `summary`

> Ваш сайт открылся на телефоне.
>
> - **Порт** — номер квартиры: адрес ведёт к устройству, порт — к программе на нём. Пишут через двоеточие: 192.168.1.42:5173.
> - **localhost** — всегда «я сам». С телефона `localhost` ведёт в телефон, а не в ноутбук.
> - Dev-сервер по умолчанию пускает только сам ноутбук. С `--host` он открывает дверь для домашней сети, и телефон заходит по адресу ноутбука.

**Доска.** Операций нет. Сцена: `play(Browse(phone → http://192.168.1.42:5173/), { as: 'letters' })`. Подпись до «Пуск»: «Нажмите «Пуск»: телефон снова откроет ваш сайт.»

>
> По строке Network и коду ошибки ИИ сразу поймёт, что сервер открыт только для самого ноутбука.

## 7. Подробнее · в шаге `door`

Заголовок: «Подробнее: 127.0.0.1, 0.0.0.0 и известные номера». Метка «для любопытных».

> У `localhost` есть адрес — 127.0.0.1. Его видно в выводе `ip a` в строке `lo0`: это «петля» внутри устройства, конверт по ней никуда не выходит.
>
> Когда сервер слушает 127.0.0.1, он открыт только изнутри. Флаг `--host` заставляет его слушать 0.0.0.0 — «на всех адресах ноутбука», в том числе на 192.168.1.42. Из интернета его всё равно не видно: домашние адреса работают только внутри дома (урок 9).
>
> Известные номера квартир: 80 — сайты без шифрования (http), 443 — сайты с шифрованием (https), 22 — удалённый вход (ssh), 5432 — база данных PostgreSQL. Dev-серверы любят 3000, 5173 и 8080.
>
> Конверты бывают двух видов. TCP — конверт с уведомлением о вручении: получатель подтверждает, что всё дошло. UDP — открытка без уведомления: отправили и не ждём. Сайты ходят по TCP, вопросы справочной обычно по UDP.
>
> Если телефон всё равно не открывает сайт, хотя сервер запущен с `--host`, дверь может держать файрвол ноутбука. О нём — урок 12.
>
> `/24` после адреса в выводе `ip a` — размер домашней сети. О нём — урок 8.
